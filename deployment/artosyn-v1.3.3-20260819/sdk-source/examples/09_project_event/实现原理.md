# 项目自定义事件实现原理

本文说明 `l4_project_event` 如何把地面端 Linux 产生的自定义事件发送到
天空端 Linux，并在天空端回调中执行对应动作。示例代码位于
`examples/09_project_event/project_event.c`，KT 固件侧处理代码位于
`board/KT/CODE/prj_rpc.c`。

## 1. 功能边界

本例程演示以下能力：

- 地面端 Linux 主动发送项目自定义命令。
- 命令通过无线链路到达天空端 8030。
- 天空端 8030 将命令转换为 `BB_EVENT_PRJ_DISPATCH` 事件。
- 天空端 Linux 订阅事件，在异步回调中更新软件状态。
- 使用 `0xff` 表示 `ARMED`，使用 `0x00` 表示 `DISARMED`。

当前“对应动作”仅为修改例程内存中的软件状态并打印日志，不会控制真实飞控、
电机或其他硬件。客户集成时应把实际业务动作接入回调后的工作线程或业务状态机。

## 2. 总体数据链路

```text
地面端 Linux
  l4_project_event -t armed -s 0
        │
        │ BB_REMOTE_IOCTL_REQ
        │ msg_id = BB_SET_PRJ_DISPATCH
        ▼
地面端 8030
        │
        │ XDS 远程命令控制通道
        ▼
天空端 8030
  bb_ioctl(NULL, BB_SET_PRJ_DISPATCH, ...)
        │
        │ prj_rpc_set(PRJ_CMD_EVENT_DEMO)
        │ bb_event_publish(BB_EVENT_PRJ_DISPATCH, &event)
        ▼
天空端 Linux
  l4_project_event -r
        │
        │ project_event_cb()
        ▼
  更新 ARMED / DISARMED 软件状态
```

地面端和天空端运行同一个 `l4_project_event` 程序，通过参数选择发送模式或
接收模式。

## 3. 自定义协议格式

项目事件使用固定的 256 字节缓冲区。缓冲区开头为通用头
`prj_rpc_hdr_t`，头部后面保存命令对应的数据结构。

现有公共定义如下：

```c
typedef struct {
    uint8_t cmdid;
    uint8_t padding[3];
    uint8_t data[0];
} prj_rpc_hdr_t;

typedef struct {
    uint8_t data;
} prj_cmd_event_demo_t;
```

本例程的数据布局为：

| 偏移 | 长度 | 内容 |
| --- | ---: | --- |
| 0 | 1 字节 | `cmdid = PRJ_CMD_EVENT_DEMO`，当前值为 200 |
| 1 | 3 字节 | `padding`，保持为 0 |
| 4 | 1 字节 | `prj_cmd_event_demo_t.data` |
| 5～255 | 251 字节 | 保留，保持为 0 |

业务数据定义：

| `data` | 含义 |
| --- | --- |
| `0x00` | `DISARMED` |
| `0xff` | `ARMED` |
| 其他值 | 非法，发送端或固件拒绝处理 |

`cmdid` 相当于数据类型。接收端必须先检查 `cmdid`，再把 `hdr->data`
转换为对应的数据结构，不能对所有项目事件都直接使用
`prj_cmd_event_demo_t` 解析。

## 4. 地面端发送实现

发送命令示例：

```sh
./l4_project_event -t armed -s 0 -i 0
```

其中：

- `-t armed` 表示发送 `ARMED` 状态。
- `-s 0` 表示目标为无线链路上的 slot 0。
- `-i 0` 表示使用本机 daemon 枚举出的第 0 台 8030。

程序首先构造项目命令：

```c
bb_set_prj_dispatch_in_t request;

memset(&request, 0, sizeof(request));

hdr = (prj_rpc_hdr_t *)request.data;
hdr->cmdid = PRJ_CMD_EVENT_DEMO;

event_demo = (prj_cmd_event_demo_t *)hdr->data;
event_demo->data = 0xff;
```

完整清零请求结构非常重要，可以保证 `padding` 和保留区域不会包含未初始化
数据。

然后将项目命令封装为远程 ioctl：

```c
bb_remote_ioctl_in_t remote_in;

memset(&remote_in, 0, sizeof(remote_in));
remote_in.slot = 0;
remote_in.len = sizeof(request);
remote_in.msg_id = BB_SET_PRJ_DISPATCH;
memcpy(remote_in.data, &request, sizeof(request));

ret = bb_ioctl(handle, BB_REMOTE_IOCTL_REQ, &remote_in, &remote_out);
```

这里必须使用 `BB_REMOTE_IOCTL_REQ`。如果地面端直接调用
`BB_SET_PRJ_DISPATCH`，命令只会交给地面端本机连接的 8030，不会到达天空端。

## 5. 无线远程命令通道

当前 KuTian 固件内部使用 XDS 远程命令控制通道承载
`BB_REMOTE_IOCTL_REQ`。远端 8030 收到请求后，会调用：

```c
bb_ioctl(NULL,
         BB_SET_PRJ_DISPATCH,
         remote_data,
         remote_output);
```

因此天空端最终进入本地 `prj_rpc_set()`。

需要注意：

- 自定义业务协议不是 XData 透传协议。
- 不需要新增 XData `msg_id`。
- 不使用 `BB_SET_PRJ_DISPATCH2`。
- 不要求工作模式为 `USR_WORK_MODE_UAV`。
- 当前远程 ioctl 实现需要固件启用 `FEATURE_NEW_XDATA`。
- 两端必须启用可用的 `xds_sync_config`，并正确配置目标 slot。

## 6. 天空端固件事件发布

KT 客户代码位于：

```text
board/KT/CODE/prj_rpc.c
```

构建 KT 板型时，`p401_build_coolsky.sh` 会把该文件临时覆盖到：

```text
apps/tests/p401/prj_rpc.c
```

参与固件编译，构建结束后恢复公共 SDK 文件。因此客户差异只维护在
`board/KT/CODE`，不直接修改公共 SDK。

天空端进入以下命令分支：

```c
case PRJ_CMD_EVENT_DEMO:
```

处理步骤为：

1. 从 `hdr->data` 读取 `prj_cmd_event_demo_t`。
2. 检查数据是否为 `0x00` 或 `0xff`。
3. 清零并构造 `bb_event_prj_dispatch_t`。
4. 在事件缓冲区中重新写入 `prj_rpc_hdr_t` 和业务数据。
5. 调用 `bb_event_publish(BB_EVENT_PRJ_DISPATCH, &event)`。

核心代码如下：

```c
bb_event_prj_dispatch_t event = {0};

event_hdr->cmdid = PRJ_CMD_EVENT_DEMO;
event_data->data = event_demo->data;

r = bb_event_publish(BB_EVENT_PRJ_DISPATCH, &event);
```

`bb_event_publish()` 是 8030 固件侧接口，Linux 应用不能直接调用它。

## 7. 天空端 Linux 订阅与回调

接收命令示例：

```sh
./l4_project_event -r -i 1
```

程序通过以下结构注册回调：

```c
bb_set_event_callback_t callback;

callback.event = BB_EVENT_PRJ_DISPATCH;
callback.callback = project_event_cb;
callback.user = &receive_ctx;

bb_ioctl(handle, BB_SET_EVENT_SUBSCRIBE, &callback, NULL);
```

天空端 8030 发布事件后，L4 SDK 异步调用 `project_event_cb()`。回调执行以下
处理：

1. 检查回调参数。
2. 把 `event->data` 解析为 `prj_rpc_hdr_t`。
3. 只处理 `PRJ_CMD_EVENT_DEMO`，忽略其他项目事件。
4. 校验业务数据。
5. 更新本地 `ARMED/DISARMED` 状态。
6. 打印状态变化或状态未变化。

日志示例：

```text
[BB_EVENT_PRJ_DISPATCH] cmdid=200 data=0xff
state changed: DISARMED -> ARMED
```

事件回调是异步执行的。实际项目不应在回调中执行耗时操作、阻塞等待或长时间
访问硬件；建议只复制消息并投递到工作线程，由工作线程执行真实业务动作。

程序收到 `SIGINT` 或 `SIGTERM` 后，会调用
`BB_SET_EVENT_UNSUBSCRIBE` 取消订阅，再关闭设备连接。

## 8. 返回值和 ACK 语义

地面端 `BB_REMOTE_IOCTL_REQ` 返回成功表示：

1. 请求已到达天空端 8030。
2. 天空端 `prj_rpc_set()` 已处理命令。
3. 天空端已完成 `bb_event_publish()` 调用。

它不表示天空端 Linux 回调已经执行完成，也不表示真实业务动作已经完成。

当前端到端验收条件为：

- 地面端打印远程请求成功。
- 天空端 Linux 收到 `cmdid=200`。
- 天空端打印正确的数据值。
- 天空端软件状态发生预期变化。

本例程没有实现天空端 Linux 动作完成后的反向 ACK。如业务要求可靠确认，应另外
设计 ACK 命令、序列号、超时和重试机制。

## 9. 测试方式

### 9.1 两台电脑

天空端 Linux：

```sh
./l4_project_event -r
```

地面端 Linux：

```sh
./l4_project_event -t armed -s 0
./l4_project_event -t disarmed -s 0
```

### 9.2 一台电脑

一台电脑可以完成端到端测试，但仍需要两台已配对并建立无线链路的 8030。

假设 daemon 枚举结果为：

- 地面端 8030：设备索引 0。
- 天空端 8030：设备索引 1。

终端 1：

```sh
./l4_project_event -r -i 1
```

终端 2：

```sh
./l4_project_event -t armed -s 0 -i 0
./l4_project_event -t disarmed -s 0 -i 0
```

只有一台 8030 不能验证完整链路，因为远程 ioctl 必须通过无线链路调用对端。
如果一个 daemon 不能同时管理两台设备，可以在同一台电脑启动两个 daemon
实例，分别绑定一台设备并使用不同端口，然后使用 `-p <port>` 选择实例。

## 10. 常见问题

### 发送端报告 `BB_REMOTE_IOCTL_REQ` 失败

依次检查：

- 两台 8030 是否已经配对并建立链路。
- `-i` 是否选择了地面端设备。
- `-s` 是否对应正确的远端 slot。
- 两端 `xds_sync_config.sync_en` 是否开启。
- slot 对应的 `sync_port` 是否配置正确。
- 天空端是否已经刷入包含 `PRJ_CMD_EVENT_DEMO` 分支的 KT 固件。

### 发送成功但天空端没有回调

依次检查：

- 天空端接收程序是否在发送前启动。
- 接收程序的 `-i` 是否选择天空端设备。
- `BB_SET_EVENT_SUBSCRIBE` 是否返回成功。
- 天空端 daemon 是否仍与设备连接。
- 天空端固件是否实际执行了 `bb_event_publish()`。

### 一台电脑无法区分两台设备

程序启动时会打印 daemon 枚举到的设备列表和 MAC 信息。可先分别拔插设备，
确认设备索引与地面端、天空端的对应关系。设备索引可能随连接顺序发生变化，
测试前应重新确认。

## 11. 扩展新的事件类型

增加新的业务事件时，建议按以下方式扩展：

1. 为新事件分配独立的 `PRJ_CMD_*` 命令号。
2. 在公共协议头中定义与该命令一一对应的数据结构。
3. 明确字段宽度、取值范围和字节序。
4. 发送端完整清零缓冲区，再填充头部和业务结构。
5. 固件根据 `cmdid` 校验数据并发布事件。
6. Linux 回调根据 `cmdid` 选择正确的结构解析。
7. 对耗时动作使用工作线程。
8. 如需可靠完成确认，增加序列号和应用层 ACK。

不要在同一个 `cmdid` 下随意改变结构大小或字段含义，否则不同版本固件和
Linux 应用之间可能出现协议不兼容。
